Scope: static host snapshot and red-source only; no tests, builds, live volume, or other model outputs. Verify-tier source fallback; graph/index/coverage unavailable. Pixel checks do not establish Vulkan API validity. No claim of exhaustive delta review.

1. **High, confirmed, high confidence — narrow primary layout state mismatch.** production-source/crates/reims-vgpu/src/backend/vulkan/engine/caches.rs:662,676,2152 and exec.rs:4633,5558,5588,5690. With COLOR_GENERAL=off, selected input 0, non-host-accessible and non-feedback, entry/subpass is GENERAL but final is COLOR_ATTACHMENT_OPTIMAL. The LOAD initial value is final even when the explicit entry barrier already moved to GENERAL; a ready ColorWrite exit also suppresses the necessary transition. Post-pass readback names GENERAL as old layout and restores GENERAL while registry claims final OPTIMAL. These are separate scenarios; Vulkan requires oldLayout to match current layout or UNDEFINED, and render-pass initialLayout to match when not UNDEFINED. https://docs.vulkan.org/refpages/latest/refpages/source/VkImageMemoryBarrier.html . Change LOAD initial to actual entry for preserve; skip only when tracked prior layout equals required entry (and existing access eligibility still holds); readback must start at actual final and restore final before registry publication. Preserve feedback and host-accessible behavior and explicit synchronization scopes. Test transitions through actual execution owner, not only synthetic helper values.

2. **High, confirmed, high confidence — sparse ordinal admission.** color_input.rs:66 and caps/device_features.rs:1013; caches.rs:645 and exec.rs:2984. One selected ordinal 7 produces span 8 but count 1; the current guard accepts it on stage limit 4. The input index limit comes from maxPerStageDescriptorInputAttachments, not maxDescriptorSetInputAttachments: https://docs.vulkan.org/spec/latest/chapters/interfaces.html and https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceLimits.html . Dynamic layout actually creates one fragment-stage binding with descriptorCount=1 per selected input; holes in pInputAttachments are not descriptors. Therefore count must fit both stage and set descriptor limits, while highest selected index/span must fit the stage index limit independently. Keep separate properties; span against min(stage,set) falsely rejects a valid sparse table when set < span. Red test with merged limit 4 cannot distinguish these cases; add asymmetric capability tests and boundaries. Existing color_input.rs:141 asserting slot 7 accepted at limit 1 must change.

3. **Medium, confirmed, high confidence — probe restart mismatch and incomplete test coverage.** exec.rs:5434-5478 uses target_pass_layout for old and new after a pass that has already transitioned to final. For selected primary under narrow policy, old is wrong. Its restarted render pass exits at final again; readback and registry must continue from final. The red restart helper test correctly asks for final-to-entry, but misses the independent layout-churn probe, exec.rs:5480-5524, which names global exit rather than actual key final. Host-accessible non-feedback target can have GENERAL final while narrow global exit is OPTIMAL; check reachability and fix probe to use actual final, including restore. Secondary attachments in the restarted pass also need validation: original pass may exit at final and restart LOAD initial uses entry; ensure their barriers or decline probe for incompatible cases. Do not assume primary-only barrier suffices.
